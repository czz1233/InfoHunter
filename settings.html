抓取行为
安全模式 开启时只抓取 JS 资源；关闭后会抓取 src/href 里的全部地址（含 css、图片），可能产生预期外请求
自动超时 开启后单个请求超时 2 秒，关闭则 8 秒
Sourcemap 抓取低风险 发现 .js.map 后拉取并还原原始源码路径与源码内容，二次提取。对 Webpack / Vite 站点价值极高。 地图地址是站点自己在注释里声明的，单个 GET、并发 3、最多 20 个
JS 递归抓取（depth 2）中风险 从已抓到的 JS 里再抽动态 import 与 chunk 引用并抓取。只取同源、只抓代码里真实引用的地址， 不做 URL 猜测。会提前拉取懒加载资源形成请求突发，最多 30 个、并发 2
框架运行时分析 读取 Vue / Next.js / Nuxt / React Router 的路由表与全局配置（在主世界执行）
运行时观测零请求
下面三项都是被动记录——只把页面本来就会做的事记下来，不发起任何请求， 因此不占用请求边界里的风险额度。收的是「浏览器实际做了什么」，与静态扫描看到的 「HTML 里写了什么」互补。
网络请求记录 记录页面实际发出的 XHR / fetch 地址、请求方法与查询参数名。 已按白名单过滤，白名单站点一个请求都不记；4xx/5xx 不记（噪声太大）。
运行时钩子 在主世界包装 fetch、XMLHttpRequest，记录 WebSocket / SSE / Worker 端点与本地存储（Web Storage、cookie）的键名与值， 并在页面读取响应体的那一刻旁观数据 —— 接口 JSON 里的手机号 / 邮箱 / 凭据由此入库， 标注来源 [response-body]；存储值命中的凭据标注 [storage-value]。 钩子只做记录，不改变原调用行为、不发起任何请求；装上之前会探测宿主环境，装不上就跳过。
SPA 增量补扫 单页应用路由切换后懒加载进来的 script，首屏扫描抓不到。开启后监听 DOM 插入， 新出现的脚本地址会补抓（每批 20 个、3 分钟后停止）。
并发数 同时抓取的 JS 数量。目标站点较慢时调低
全局悬浮窗 在每个页面上显示结果面板
域名白名单
使用内置默认名单 内置名单分两层：站点级（搜索引擎、社交、电商、代码托管、邮箱、大厂官网、安全社区等， 命中的页面完全不扫描）与资源级（统计、广告、风控、客服、地图、错误监控、公共 CDN 等第三方 SDK， 页面照扫但这些脚本跳过不抓）。下面填的条目是叠加在内置名单之上的，关掉这里才只认你自己填的。
